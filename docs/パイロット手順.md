# パイロット手順（テスト患者・自分の iPhone で試す）

## 段階 1: 今すぐ試す（Mac のテスト環境、Google 不要）

Mac でモックサーバーと開発サーバーが起動している状態で行う（起動方法は `tools/mock-server/README.md`）。

1. iPhone を **Mac と同じ Wi-Fi** につなぐ
2. Safari で `http://<Mac の IP>:5173` を開く（IP は Mac のターミナルで `ipconfig getifaddr en0`）
3. 共有ボタン → **ホーム画面に追加** → 追加
4. ホーム画面の「術前リハ」アイコンから開く（Safari のタブではなく、必ずアイコンから）
5. 番号 `9001`、暗証番号 `0000` を入力して「設定する」→ セッションの曜日を選ぶ
6. 「セッションを始める」→ 体調確認で「症状なし・概ね元気」（青）や「だるい」（黄＝軽いメニュー）や「38 ℃以上の熱」（赤＝中止）を試し、終了後「運動後の体調を記録して送る」まで進めて送信する
7. Mac のブラウザで `http://localhost:8787` を開くと、記録と即時通知（メール相当）が表示される

この段階で確認するのは、画面の見やすさ、文言、入力の手間、セッションの進め方。Google 側はまだ関係ない。

## 段階 2: 本番と同じ経路で試す（Google Workspace ＋ GitHub Pages）

### 2-1. スプレッドシートと Apps Script（大学アカウントで 15 分）

1. 大学 Google アカウントで Google ドライブを開き、**共有ドライブ**を新規作成（名前は例: `術前リハ`）。メンバーは自分だけでよい
2. その中に **Google スプレッドシート** を新規作成（名前は例: `術前リハ_記録`）
3. メニュー **拡張機能 → Apps Script**
4. 左の `コード.gs` の中身を全部消し、`apps-script/Code.gs` の内容を貼り付けて保存（Ctrl/Cmd+S）
5. 左の歯車（プロジェクトの設定）→「`appsscript.json` マニフェスト ファイルをエディタで表示する」にチェック → 左に出た `appsscript.json` を `apps-script/appsscript.json` の内容で置き換えて保存
6. 上部の関数選択で **setupSheets** を選び「実行」。権限の確認が出たら自分のアカウントで許可（「このアプリは Google で確認されていません」と出たら「詳細」→「（安全ではないページ）に移動」）
7. スプレッドシートに戻り、**設定**タブの `notify_emails` に自分の大学メールを入力
8. Apps Script に戻り、関数 **installTriggers** を実行
9. 関数 **testPostDummy** を実行 → スプレッドシートの日次記録に 1 行入り、自分のメールに通知が届けば OK（ダミー患者 9001 が患者一覧に追加される）
10. 右上 **デプロイ → 新しいデプロイ** → 種類「ウェブアプリ」→ 実行ユーザー「自分」→ アクセスできるユーザー「**全員**」→ デプロイ
11. 表示された **ウェブアプリの URL**（`https://script.google.com/macros/s/.../exec`）をコピーして控える
12. Safari でその URL を開き `{"ok":true,"service":"prehab",...}` と出れば公開できている

> 手順 10 で「全員」が選べない場合は大学の Workspace 設定で制限されている。その時点で止めて相談（Google フォーム方式に切り替える）。

### 2-2. 患者アプリを GitHub Pages に置く（20 分）

GitHub のアカウントが必要（無料）。GitHub Pages は無料アカウントでは公開リポジトリのみ。アプリ本体には患者データも秘密情報も含まれないので公開で問題ない。

ターミナルを使わずに済む **GitHub Desktop** を使う手順で書く。

**A. アカウントと GitHub Desktop**

1. https://github.com で「Sign up」→ メール・パスワード・ユーザー名を決めて登録（大学メールでよい）
2. https://desktop.github.com から GitHub Desktop（Mac 版）をダウンロードしてインストール → 起動 → 「Sign in to GitHub.com」でログイン
3. 初回に名前とメールの確認画面が出たらそのまま「Finish」

**B. このフォルダを GitHub に載せる**

4. GitHub Desktop のメニュー「File」→「Add Local Repository」→「Choose…」で `術前リハアプリケーション` フォルダを選ぶ
5. 「This directory does not appear to be a Git repository」と出るので、その文中の **「create a repository」** をクリック → 出てきた画面はそのまま「Create Repository」
6. 左下の「Summary」欄に `initial` と入力して **「Commit to main」**
7. 上部の **「Publish repository」** を押す → Name は `prehab-app` のままでよい → **「Keep this code private」のチェックを外す** → 「Publish Repository」

これで https://github.com/<ユーザー名>/prehab-app にフォルダの中身が載る。

**C. 公開の設定（ブラウザで GitHub を開く）**

8. https://github.com/<ユーザー名>/prehab-app を開き、上部タブ **「Settings」**
9. 左メニュー **「Pages」** → 「Build and deployment」の「Source」を **「GitHub Actions」** にする（保存ボタンはない。選ぶだけ）
10. 左メニュー **「Secrets and variables」→「Actions」** → 上のタブを **「Variables」** に切り替え → **「New repository variable」** で次の 3 つを 1 つずつ追加
    - Name `VITE_API_URL` / Value: 2-1 で控えた Apps Script のウェブアプリ URL
    - Name `VITE_HOSPITAL_PHONE` / Value: テスト中は自分の携帯番号など
    - Name `VITE_HOSPITAL_NAME` / Value: `順天堂医院 肝胆膵外科外来`
11. 上部タブ **「Actions」** → 左の「Deploy patient PWA to GitHub Pages」→ 右の **「Run workflow」→「Run workflow」**
    - 初回の push 時にも自動で 1 回走っているが、Pages の設定前だと失敗しているので、ここで改めて実行する
12. 2〜3 分待ち、緑のチェックになれば完了。Settings → Pages の上部に公開 URL が表示される（`https://<ユーザー名>.github.io/prehab-app/`）

**D. 以後の更新**

アプリを修正したら、GitHub Desktop を開き、Summary に一言入れて「Commit to main」→「Push origin」。2〜3 分で自動的に公開版が更新される。患者側は次にアプリを開いたときに新しい版になる。

**うまくいかないとき**

| 症状 | 対処 |
|---|---|
| Actions が赤い × | クリックして赤い箇所を開く。「Pages」の設定前なら Settings → Pages を GitHub Actions にして Run workflow をやり直す |
| 公開 URL を開いても真っ白 | Variables の名前の綴り（`VITE_` から始まる）を確認。直したら Run workflow をやり直す |
| 「通信できませんでした」と出る | `VITE_API_URL` が Apps Script の `/exec` で終わる URL か確認 |

### 2-3. テスト患者を発行して iPhone で試す

1. Mac で `tools/id-generator/index.html` をブラウザで開き、番号を `9001` にして「発行する」（暗証番号が自動生成される）
   - 2-1 の手順 9 で 9001 が既に患者一覧にある場合は、その行を削除してから貼り付ける
2. 「患者一覧タブに貼り付ける行」をコピーし、スプレッドシートの患者一覧の空行（A 列）に貼り付け。`assignee_dr` に自分のメールを入れる
3. 「印刷」でカードを出す（画面で見るだけでもよい）
4. iPhone の Safari で `https://<ユーザー名>.github.io/prehab-app/` を開く → 共有 → ホーム画面に追加
5. ホーム画面のアイコンから開き、番号と暗証番号を入力 → 「設定する」→ セッションの曜日を選ぶ
6. セッション → 記録送信まで行う
7. スプレッドシートの日次記録に行が入り、赤信号なら即時通知メールが届く。全体サマリーと「進捗_9001」タブが更新される
8. 翌朝 8 時に朝のまとめメールが届くことを確認

### うまくいかないとき

| 症状 | 見るところ |
|---|---|
| 「番号または暗証番号が違います」 | 患者一覧の `study_id` が `9001` と文字列で入っているか（`9001.0` や数値になっていないか）。`pin_hash` が発行ツールの出力と一致するか |
| 「通信できませんでした」 | GitHub の Variables に `VITE_API_URL` が入っているか。Apps Script の URL を Safari で開いて JSON が返るか |
| 通知メールが来ない | 設定タブの `notify_emails`。通知ログタブに「宛先未設定」と出ていないか。迷惑メールフォルダ |
| ホーム画面から開くと設定画面に戻る | iOS は Safari とホーム画面アプリで保存領域が別。ホーム画面のアイコンから開いて番号を入力し直す |
| Apps Script のコードを直した | デプロイ → デプロイを管理 → 鉛筆 → 新バージョン → デプロイ。URL は変わらない |

### テストが終わったら

- 患者一覧の 9001 の `status` を `inactive` にするか行を削除
- 日次記録・対応記録・通知ログのテスト行を削除
- 実患者の運用開始前に、`VITE_HOSPITAL_PHONE` を外来の番号に変更して再デプロイ
